# C4 data provenance audit

The 50 examples in `ml/lora/datasets/test.jsonl` contain synthetic contexts
generated by `gen_contexts.py`, not live-scenario contexts captured by
`capture_real.py`. The original metric values are retained, but they must be
described as results on a fixed synthetic test set, never as performance on
real-world observations.

## Reproducible check

```bash
cd /Users/chrisjiang/Projects/harborguard
.venv/bin/python acceptance_c4/data_provenance_20261017/audit_provenance.py
```

The script only reads files. It does not call cloud services, Ollama or the
backend. It checks frozen hashes, record-by-record source membership, the
ordering reconstructed by `split_records(seed=0)`, the Lenovo training input
hash and the 493/8 split record.

## Provenance chain

- Raw synthetic contexts: 500 in `contexts.jsonl` and 80 in
  `contexts_extra.jsonl`.
- Eligible synthetic distillation records: 552, sorted by key and then shuffled
  with `seed=0`.
- Frozen test50: the first 50 shuffled records, including 40 from the first
  batch of 500 and 10 from the extra batch of 80.
- Synthetic train450: the following 450 records.
- Captured live-simulation contexts: 51 in `real_contexts.jsonl`, appended only
  to the end of the training file.
- Lenovo input: 501 records in `train.jsonl`, with a hash matching
  `training_meta.json`. The first 493 were used for formal training (450
  synthetic and 43 captured from live simulation); the last 8 were used for
  internal validation (all captured from live simulation).
- confirm60: a separate synthetic confirmation set with `seed=424242`, with
  zero exact context duplicates against test50.

Exact context overlap is zero for train501 vs test50, real51 vs test50, and
confirm60 vs test50. This conclusion uses SHA256 of canonical JSON contexts;
it does not prove that every synthetic scenario is semantically independent.
`real_contexts.jsonl` also lacks a capture-run ID on each record, so the file
alone cannot reconstruct the batch boundaries of the three A/B scenario
capture runs described in the handoff.

## Additional checks from this audit

- All three sets of raw synthetic contexts were reconstructed in memory using
  the current generator: 500/seed0, 80/seed1 and 60/seed424242. Original files
  were only read.
- The user JSON in `confirm60.eval.jsonl` contains serialization spaces, while
  raw contexts use compact serialization. Parsed content and ordering match
  for all 60/60 records. The audit compares canonical JSON; the original
  frozen files were not rewritten.
- confirm60 has zero exact overlap with train501, including formal train493
  and internal validation8. Neither test set has internal exact duplicates.
- The word "real" in `capture_real` means contexts obtained from a local run
  of the simulation backend. It does not mean measurements from a real sea
  area or physical sonar.
- Current files exactly match the fixed split. No evidence of test-set
  replacement was found. This hash audit cannot independently prove historical
  creation times. The generation/evaluation timeline in `FREEZE.md` remains
  an existing record; this audit does not invent a new freeze time.
- The evaluation script reads `ml/lora/datasets/test.jsonl` by default.
  confirm60 was evaluated through a separate test-path wrapper. Original log
  summaries and metrics for both runs are in the candidate directory. This
  audit did not rerun the model or change configuration.
- Integer numerators for JSON mode are uniquely recoverable from the original
  aggregates and known denominators, and are stored in the formal metrics
  `counts`. test50: structure 50/50, facts 44/50, options 31/33, null handling
  14/14. confirm60: structure 60/60, facts 39/60, options 35/36, null handling
  18/18. Latencies remain the original evaluation's 3.75/4.71 seconds.

See [audit.json](audit.json) for the complete machine-readable record. Hashes
and exact-overlap findings can be recomputed; they cannot establish semantic
independence of similar scenarios or replace real marine validation. Incorrect
provenance labels do not require withdrawing the synthetic-set results.
Claims of independent performance on real-world captures must be withdrawn.
This audit did not meet the training-overlap condition that would require
reevaluating the frozen sets.
